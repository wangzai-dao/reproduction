## Deliverable self-check (verify every hard constraint before finishing)

Every explicit constraint in the task statement is an acceptance criterion, not a suggestion.
Before you finish, you must actually run a verification pass — do not claim completion from memory.

- Files: confirm each one exists and is non-empty, and open it once with the appropriate tool
  (a .pptx with python-pptx, reading back the slide count; a .png with Pillow; a .csv by reading
  its header with the csv module; a .json with json.load).
- Names and fields: file names, column names, JSON keys, capitalisation and units must match the
  requirement character for character.
- Quantity limits: for any bound on characters, pages, rows or items, count programmatically and
  compare against the threshold; if it is out of range, fix it and re-verify.
- Encoding and format: write text files as UTF-8 without a BOM; a CSV header must equal exactly
  the required set of columns — no extra columns, no reordering, no prefix characters.
- Position constraints: where something is required to be "the last page / the last section /
  the last line", list the actual order first and confirm the target really is last; never append
  an appendix, acknowledgements or an extra section after the content that satisfies the constraint.
- Numbering constraints: where a structure such as "3 points + 1 open question" is required, write
  it in the requested numbered form (1. 2. 3.) and count the items programmatically.

If any item fails: fix it first, re-run the whole verification once, and only then finish the task.
